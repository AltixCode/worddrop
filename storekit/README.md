# StoreKit test configuration

`WordDrop.storekit` lets the purchase flow be exercised on a simulator without
App Store Connect products and without a sandbox account — which matters here,
because the App Store record does not exist yet.

Exported from the RevenueCat catalogue:

```bash
rc apps storekit-config appf5a028a41e --project-id proje05b0359 \
  --output storekit/WordDrop.storekit
```

The display price and copy in this file are **local test values**, not a claim
about what the app will cost. The shipped paywall never renders them: it reads
`product.priceString` from the live offering, so a price baked into the bundle
could not reach a player even by accident.

## Using it

`ios/` is regenerated by `expo prebuild`, so the scheme setting does not
survive and has to be selected once per generated project:

1. `npx expo prebuild --platform ios && npx expo run:ios`
2. In Xcode: *Product → Scheme → Edit Scheme → Run → Options →
   StoreKit Configuration* → `storekit/WordDrop.storekit`.
3. Run the app, open the paywall, and exercise **all four** paths, not just the
   happy one: buy, restore, cancel the sheet, and turn the network off.

What each path must do (`src/services/purchases.ts` returns a tagged union
precisely so these stay distinguishable):

| Path | Expected |
| --- | --- |
| Buy | Ads stop, the archive opens, the crown badge disappears from the header |
| Restore with an entitlement | Same, silently |
| Restore with none | "No earlier purchase was found to restore." |
| Cancel the sheet | Nothing at all — no error, no nag |
| Store unreachable | "The store is unreachable right now." and **no unlock** |

The last row is the one worth being careful about: granting Pro when the store
cannot be reached hands the unlock to anyone who taps Restore on a flight.
